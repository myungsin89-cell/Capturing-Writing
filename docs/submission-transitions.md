# 제출 회수와 교사 첨삭 전송

- 개별 첨삭, 묶음 첨삭, 최종 완성 처리와 제출 회수는 저장 직전에 최신 제출 상태와 제출본 지문을 확인합니다.
- 회수가 먼저 저장되면 이전 제출본에 대한 교사 전송을 거절합니다. 교사 화면에 회수 상태를 반영하고 작성 중인 첨삭은 유지합니다.
- 첨삭이 먼저 저장되면 학생의 회수를 거절하고 최신 공책과 첨삭 도착 안내를 표시합니다.
- 같은 요청을 재시도하거나 응답이 유실되어도 요청 영수증으로 이미 저장된 전송을 확인합니다.
- 제목·본문·차수·제출 시점이 바뀌면 이전 제출본의 전송 요청을 적용하지 않습니다.

## 동시 저장

Sheets의 `SSEUDAM_STATE_REVISION` 이름 범위 한 개를 저장 버전으로 사용합니다. 저장 전에 읽은 버전 ID를 삭제하고 다음 버전 ID를 생성하는 작업, AppState와 표시용 시트 갱신을 하나의 원자적 `spreadsheets.batchUpdate`에 넣습니다. 다른 창이 먼저 저장해 이전 ID가 없어졌으면 전체 요청이 실패합니다. 이때 최신 상태를 다시 읽고 병합·제출본 검증을 거쳐 최대 4회 시도합니다. 이름 범위는 교체하므로 요청마다 누적되지 않습니다.

교사의 일반 자동 저장도 같은 저장 경로를 사용합니다. 최신 교사 화면이 저장한 학급에는 `atomicStudentWrites`를 기록하고, 새 학생 화면의 제출·질문·회수를 같은 시트 직결 경로로 보냅니다. 기존 Apps Script 재배포를 요구하지 않습니다. 연결 권한이 만료되면 실패 안내를 표시하며, 보호되지 않은 다른 저장 경로로 우회하지 않습니다. 수업 중 열려 있던 이전 버전의 교사·학생 화면은 새로고침해야 새 경로를 사용합니다.

교사 첨삭은 제목·본문·차수별 화면 보관함에 유지합니다. 회수만으로 글이 바뀌지 않았다면 입력창 내용을 유지하며, 다른 본문으로 재제출되면 기존 첨삭을 `이전 제출본에 작성하던 첨삭`에서 참고할 수 있습니다. 새 글에 이전 첨삭을 자동 전송하지 않습니다. 이 화면 보관함은 탭을 닫으면 사라지는 메모리 보관입니다.

## 확인

`tests/submission-transition.test.cjs`는 서로 다른 클라이언트가 같은 옛 버전을 동시에 읽도록 만들어 회수/첨삭/완성 충돌, 다른 학생 동시 회수, 저장 응답 유실, 늦은 자동 저장을 확인합니다. 실제 학급이나 Google 계정에 쓰지 않습니다.
